# Эмулятор ANT BMS на Arduino Nano

Отвечает по UART (SoftwareSerial) на запрос `5A 5A 00 00 00 00` пакетом 140 байт
старого протокола ANT (`AA 55 AA FF …`, big-endian, контрольная сумма — сумма байт 4..137).
Внутри — физическая модель 20S 105 А·ч сборки, данные меняются «естественно».

## Подключение

| Nano | Куда | Примечание |
|------|------|-----------|
| D6 (RX) | TX опрашивающей платы | |
| D5 (TX) | RX опрашивающей платы | Nano выдаёт 5 В. Для 3.3 В входа без 5V-tolerance — делитель 1 кОм / 2 кОм |
| GND | GND | |
| D3 | кнопка → GND | короткое — следующий режим, долгое (>0.8 с) — перезапуск режима |
| D13 | встроенный LED | мигает номером режима |

USB (115200): статус раз в секунду и команды: `n`/`p` — след./пред. режим, `r` — перезапуск,
`<номер>`+Enter — выбрать режим, `l` — список, `x` — hex-дамп отправляемых пакетов.

## Файлы

- `config.h` — **все настройки**: число ячеек, ёмкость, химия (NMC/LFP), уставки защит, скорость UART, знак тока, пины.
- `modes.cpp` — **режимы** и профили тока.
- `battery_model.*` — модель сборки (OCV, внутреннее сопротивление, поляризация, тепло, CC/CV зарядник, балансир, защиты).
- `ant_packet.*` — сборка 140-байтного пакета по смещениям из документации (независимо от вашей структуры, поэтому эмулятор заодно проверяет её).
- `emulator.*` — связка модели, режимов и протокола; не зависит от железа (собирается и на ПК для тестов).

## Режимы

| # | Режим | Что видно |
|---|-------|-----------|
| 1 | Заряжена, покой | 100 %, 0 А, авто-балансировка (статус 4) |
| 2 | Плавный разряд (×20) | ~18 А с колебаниями, SOC и напряжение плавно падают |
| 3 | Езда (×1) | разгоны до ~140 А, просадки ячеек, рекуперация, стоянки |
| 4 | Средне разряжена, покой | 50 %, 0.3 А собственного потребления |
| 5 | Сильно разряжена (×10) | 7 % → срабатывает защита, ключ разряда = 2 |
| 6 | Зарядка CC/CV (×30) | 30 А → CV → окончание, счётчик BMS калибруется на 100 % |
| 7 | Дозаряд + балансировка (×10) | 92 %, большой разбаланс, балансир (статус 2), биты балансировки |
| 8 | Разбаланс, слабая ячейка #7 (×10) | ячейка 7 «уходит вниз» под нагрузкой |
| 9 | Перегрев (×5) | ключи греются до 90 °C → статусы 7, остывание, повтор |
| 10 | Сбой: нет ответа | проверка обработки потери связи |
| 11 | Сбой: битая контрольная сумма | каждый 2-й пакет с неверной суммой |

`×N` — ускорение модельного времени, чтобы заряд/разряд 105 А·ч проходили за минуты.

## Как добавить режим

В `modes.cpp`:

```cpp
static const char N_WINTER[] PROGMEM = "Зима, езда";
...
//   name      profile     p1      p2     p3    soc spread weak amb speed faults
{ N_WINTER, prof_drive, 120.0f, 10.0f, 0.3f,  60,  5,    0,  -15,  1,  FAULT_NONE },
```

Нужен свой характер тока — напишите функцию `float prof_xxx(const ModeDesc &m, float t)`,
возвращающую ток в амперах (`> 0` — нагрузка, `< 0` — зарядник) в момент `t` (модельные секунды).
Ограничения CC/CV, защиты и балансировка применяются моделью автоматически.

## Что стоит сверить с реальной BMS

- `CFG_DISCHARGE_NEGATIVE` — знак тока и мощности (документация его не описывает).
- `CFG_BMS_BAUD` — 19200 у большинства плат (ESPHome), в PDF ANT указано 9600.
- Порядок 6 температур — сделан как в `BMSAnt_Data.h` (MOSFET, балансир, T1..T4).
